# huashu-motion 研究與作者影片流程強化

日期：2026-10-21
對象 repo：alchaincyf/huashu-motion（skill 版本 0.1.1；本文件依據其 SKILL.md 與 references 實讀整理）
任務前提（作者指定）：先判斷它與現行做法有沒有明顯差異；沒有取代性的差異，就讀它的 code 與邏輯，用來強化現行流程與 Prompt。

## 一、它是什麼，跟 HyperFrames 的關係

技術底座相同：影片是一份 HTML 合成（HTML + GSAP 動畫），在 Chrome 裡逐幀渲染成 MP4。
差別在上層：HyperFrames 是平台（21 個 skills、雲端渲染、通用工作流）；huashu-motion 是一套導演方法論加互動迴圈，專攻產品發表片與解說片。值得讀的是它的方法，不是它的渲染。

## 二、它的 code 與邏輯拆解

### 1. Contract（合成的寫法紀律）
- 一切都是時間的函數：禁用 `Date.now()`、未設種子的隨機、網路請求。隨機用 `OM.random(seed)`，彈簧動畫用閉式解 `OM.spring()`。任何一幀單獨跳過去看，跟連續播放看到的必須一致，否則 check 會報 history-dependent 警告。
- 可編輯值全部宣告成 composition variables（標題、關鍵數字、顏色、停留秒數），綁在 HTML 屬性上，使用者能在 studio 裡直接改，不必透過 agent。
- 每個可能被指到的物件都有 `data-om-id`，場景是時間軸標籤。聲音是宣告不是剪輯：`OM.sfx('thud', t)` 在動畫落點那一行標記音效；音樂是寫在合成裡的樂譜（ABC 記譜）或內建方向，`om sound` 據此生成音軌，改時間就自動重生。
- 動畫只准動 transform（x、y、scale、rotation），不准動 left/top/width，check 會拒絕 layout 動畫。

### 2. 導演流程（9 步，順序有意義）
1. 先 `om learn`：讀這位使用者過去影片留下的偏好與經驗，再讀產品（網站、UI、品牌、數據），找訊息的形狀與品牌性格，選格式與動態語言。口播方式在這步定死（無旁白、系統聲、本人錄音、素材原聲）。
2. 三個方向：差異必須在動態語言或材料，不准只是換顏色。每個方向一張真實關鍵幀加一張說明卡，附色票（palette 要寫出來源），用 `om swatch` 並排檢查對比與「會不會像大家都在用的那種長相」。
3. Treatment 先行：`treatment.md` 沒寫完不准動工。內容是節奏表與 beat map、四張靜幀（hook、hero、最密、結尾）、連續性鏈。
4. 先做最難的一鏡，做到全解析度正確，再往外擴。
5. 看片：`om check` 零錯誤，再逐幀看關鍵時刻，特別看每次換場後的第一秒（提早閃現的元素只在那裡現形）。
6. 聲音：旁白先行、音樂在旁白下自動 duck。發表片走 composer mode，自己寫譜對位畫面；每個重要落點都要有 hit，30 秒約 8 到 15 個。因為 agent 聽不到，用頻譜圖檢查能量。
7. 交 studio 給使用者指點（迴圈見下）。
8. 匯出：迭代不用 motion blur（30 秒片約 12 到 15 秒渲完），最終版才開（慢動作或快速 UI 移動時）。
9. Harvest：使用者簽核後，把這支片的評論與修改整理進經驗檔，下一支片的起點因此往前。

### 3. 節奏方法（rhythm.md，有實測數據）
- 先選路線：Continuous（一鏡到底的世界）、Montage（每刀踩拍）、Hybrid（連續主幹加一兩段蒙太奇爆發，多數發表片屬此類）。
- 能量曲線先畫：0 到 10 分段評。3 秒內要有 hook（21 支實測發表片中 14 支如此）；能量要階梯式爬升不要斜坡；中段要有最密的 burst；結尾前要有一次停頓再落。
- 實測基準：21 支發表片中 15 支每分鐘切 10 次以上，音樂驅動型平均一鏡 1.8 到 3.5 秒。「無聊」的形狀被明確定義：每 4 到 5 秒才一個事件、每場同一個動作、全片同一種 ease。

### 4. 指點式修訂迴圈（studio / inbox / look / done）
- 使用者在預覽裡點某一幀的某個物件留言，agent 收到的是：留言、時間點、被點物件與其原始碼行號、當下變數值。先 `om look` 看那一幀與點擊處特寫，再動手。
- 修訂原則：只改被指的地方，其他全部不動；能用變數改的就用變數改（最小變更）；時間類要求（多停一拍）要把後面順延但事件對位不變。做完用一句使用者的語言回報改了什麼。
- 每個版本都留 history，`om undo` 永遠可用。

### 5. 經驗系統（learn / harvest）
- 三種條目嚴格分開，永不混寫：preference（使用者原話引用，對他有效直到他改口）、observed（單支片的觀察）、verified（兩支片重現或有量測）。
- 順序紀律：先修被新證據推翻的舊條目；能被工具抓到的問題就改工具（加進 qa 檢查），不要寫成經驗條目；剩下的才寫進經驗檔。個人的口味永遠不升級成出貨規則。

## 三、差異判斷：對你的現行做法

你的現行管線是生成式：角色設定圖、逐鏡首幀圖（生成模型，含你自己在 Grok 生的圖）、圖生影逐鏡生成、剪輯組裝、海報從成片抽幀。核心能力是「演出」：角色、場景、表演，這是 huashu-motion 做不到的，它沒有生成像素的能力，只有排版與動畫。

所以結論分兩層：
- 產出層：沒有取代性差異。它不能做你的敘事短片，這條不成立，不需要換工具。
- 方法層：有四個真差異，而且都可移植到生成式管線：(1) 動工前的節奏設計（能量曲線與 beat map） (2) 聲音在創作當下就標記落點，而不是剪完再配 (3) 指點式修訂的精度紀律 (4) 每支片的經驗收割。以下強化就是把這四件移植進你的流程。

## 四、強化後的流程（你的管線 v2）

在你現有五步（概念 → 角色與首幀 → 逐鏡生成 → 剪輯 → 抽幀衍生）的前後與中間，插入四個環節：

0. **方向階段（新增，在概念之後、生成之前）**：產出 3 個方向，每個含：一張關鍵幀（用生成圖做，要最能代表全片的那一格）、色票與其來源、動態語言一句話（例：踩拍蒙太奇、緩推連續）。三個方向要在動態語言或材料上不同，不准只有顏色不同。選定後寫一頁 treatment：能量曲線（分段 0 到 10)、3 到 5 個音樂同步點（hook、轉折、停頓、揭露、Logo)、四張靜幀位（開場、主角、最密、結尾）。
1. **分鏡表升級**：每鏡多三欄，節奏拍點（這一鏡落在第幾拍、能量值）、聲音落點（哪一幀要有什麼 hit)、連續性（這一鏡從上一鏡接什麼元素或動作）。生成 prompt 從分鏡表出，不再逐鏡臨場寫。
2. **聲音地圖隨片生成**：逐鏡生成時就把 OM 式落點標進分鏡表；組裝時音樂能量曲線對照 treatment 的曲線檢查一次（你聽得到，我看不到，所以我這側用波形與頻譜圖核對能量形狀）。
3. **QA 關卡（新增，在交付前）**：逐項過清單（見 Prompt D)：換場後第一秒有沒有閃現、單幀 pop、死時間（超過 1.5 秒無事件）、能量曲線是否平坦、結尾有沒有品牌落點。過不了的鏡頭才回去重生，不整支重做。
4. **Harvest（新增，簽核後）**：把你這支片的回饋原話、我的觀察、量測到的數據分三類記入你的影片偏好檔；下次開案先讀。被推翻的舊條目先修，能變成檢查項的進 QA 清單。

## 五、強化版 Prompt 模板（可直接複用）

### A. 方向階段 brief（給生圖或給我）
```
為 [產品/主題] 做一支 [秒數] 秒 [橫/直] 式短片，先給我 3 個方向，不要直接做片。
每個方向交：一張關鍵幀（全片最有代表性的一格）、色票（3-5 色，註明來源：品牌色/場景/參考片）、
動態語言一句話、能量曲線草圖（分段 0-10，標出 hook、burst、停頓、結尾落點）。
三個方向必須在動態語言或材料上不同，只有顏色不同不算。
限制：[品牌規範/禁用元素]。受眾：[誰]。要傳達的只有一句話：[訊息]。
```

### B. 分鏡表（含節奏與聲音欄位）
```
依選定方向與 treatment，把分鏡表列完再開始生成。每鏡欄位：
鏡號｜時間（起-止）｜畫面（構圖與主體）｜動作（一個動詞）｜拍點（第幾拍/能量值）｜
聲音落點（落點幀＋音效或音樂事件）｜連續性（接上一鏡的元素或動作）｜生成 prompt｜首幀來源
規則：3 秒內出現 hook；每鏡長度對照能量曲線，高能量段鏡頭短；換場要嘛踩拍、要嘛有元素承接，不准無理由硬切。
```

### C. 指點式修訂（你給我回饋時，或我自檢時）
```
修訂格式：[時間點] 的 [物件/元素]，[現在的問題]，改成 [期望狀態]，其他不動。
收到後我先截那一幀確認落點，只動被指的鏡頭或元素；涉及時間的修改，後面順延但事件對位不變；
改完用一句話回報：改了什麼、影響範圍到哪。
```

### D. 完片 QA 檢查（交付前我跑一次）
```
逐項檢查並給證據（時間點）：
1. 每個換場後第一秒：有無元素提早閃現或黑幀
2. 單幀 pop：有無只出現一幀的異物或跳變
3. 死時間：超過 1.5 秒無任何事件的段落列出
4. 能量曲線：實際節奏與 treatment 曲線對照，哪段平了
5. 聲音落點：分鏡表標記的 hit 是否都在落點幀上，音樂 duck 是否壓住旁白段
6. 結尾：品牌落點是否成立，最後一幀是否可當海報
不合格的只列鏡號與問題，不重做整支。
```

## 六、備註

- huashu-motion 的 om 工具鏈（studio 指點、變數編輯、自動音軌）只對它自己的 HTML 合成有效，移植到生成式管線的是方法與紀律，不是工具本身。
- 它與 HyperFrames 同底座：若日後有動態圖形類的片（產品解說、數據片），兩者才是直接選項；敘事生成片繼續用你現在的管線加這份 v2 方法。
